Quality gates applied to every training row

  • Feed gate — kiln feed > 461 t/h only; the twin never learns from shutdown/upset data.
  • Analyser purge masking — CO/O₂ readings valid only when RUN=1 and O₂ < 15% (purge cycles produce ~9% outliers — confirmed by the upstream IQR outlier report, whose cleaning proved equivalent to our gates: identical 388k rows after both).
  • Dead-tag exclusion — 423CN150_TT_1 / 423KR405_TT_3/4 exist in history but are dead on the live server; any feature built on them invalidates every live row, so they are banned (rule enforced in code).
  • Forward-gap guards — a t+5 target must really be 4–7 min ahead; data gaps can't fake targets.
  • Lever forward-fill — setpoints hold until moved; gaps in manipulated variables are filled, rates correctly read 0.
  • Chronological splits only — random splits leak adjacent minutes and flatter every metric.

Three data bugs found and fixed (Aug 21) — worth recording

① Historian timestamps carry microseconds, live ones use ISO-'T' — the format clash silently excluded all live rows from training (fixed: normalisation + mixed-format parsing). ② v2 features referenced dead OPC tags → every live row invalid (fixed: live-computable features only). ③ A tag-name typo (K3V10F1 vs K3V10_F1) meant the AFR tertiary-air damper was never captured by the live feed for a month (fixed + backfilled via forward-fill). Each fix is now a permanent guard in the pipeline.

03The autonomous weekly retrain cycle

Every Sunday at 02:00 the system retrains itself: matured live minutes are ingested into the historian, the full model (4 horizons × mean/P10/P90 + safety heads + ARX blend) retrains, and the candidate is promoted only if its test MAE is at most 115% of the incumbent's — otherwise the previous bundle is restored automatically. The incumbent is always backed up first; serving and shadow reload on promotion. Nine cycles have run; every one promoted; zero manual interventions.

04Accuracy metrics — what each one actually tells you

No single number describes a forecasting system honestly. These are the eight we track, what each reflects, and what each hides:

MAE — mean absolute error (°C)

The average miss. Our headline: every prediction, on average, lands within ±5.98 °C offline / ±6.56 °C live.

⚠ Hides direction (bias) and tail behaviour; incomparable across time windows — always read beside persistence.

Forecast skill (%)

1 − MAEmodel/MAEpersistence on the same minutes. THE defensible number: 25% offline, 22% live. Skill is window-invariant — it survived the volatile week when raw MAE doubled.

⚠ Persistence must be computed on the identical timestamps or it's meaningless.

RMSE — root mean squared error (°C)

Like MAE but punishes big misses quadratically (8.1 vs 5.98 offline). The RMSE−MAE gap says errors have tails — occasional large moves get missed.

⚠ Dominated by the same volatile periods that inflate persistence.

R² — variance explained

0.689: the twin explains ~69% of temperature variance at t+5. Good for statisticians; less intuitive for operators.

⚠ Inflated by regime spread — a model that just tracks the band level scores well. Delta-space R² is far harsher.

Interval coverage (%)

How often truth lands inside the P10–P90 band. Design target 80%; measured 82–84% live via conformal recalibration (band width re-fit from live residuals every 6 h).

⚠ Coverage without width is gameable — a huge band always covers. We publish width (≈ ±11 °C) with it.

Live bias (raw vs served) (°C)

Rolling 2 h signed error of the raw model. Currently self-corrected: the served prediction adds back the damped offset (±10 °C clamp). Was +1.9 °C in early Aug (condition drift); now ~0–1 °C after correction.

⚠ Bias is measured against the RAW model so the correction can never hide its own input.

Damping ratio

Predicted move ÷ actual move on large swings ≈ 0.44 — the twin under-calls big moves (MAE-optimal caution). This is why a 'big-move detector' classifier is on the roadmap.

⚠ A model can have great MAE and still damp — check this before trusting it during upsets.

MRE — mean relative error (%)

The academic yardstick (error ÷ absolute temperature). Published SOTA: 0.91% ≈ 8 °C. The twin: ~0.68% ≈ 6 °C. Only used for literature comparison.

⚠ Dividing by ~880 °C makes anything look small — same trap as the retired '99%'.

Why we retired “99% accurate”

Early on, accuracy was framed as 1 − MAE/temperature ≈ 99%. A sharp reviewer dismantles this in seconds: the denominator (~880 °C) is unit-arbitrary — in Fahrenheit the same model becomes “99.5% accurate”, in kelvin better still, having predicted nothing differently. Worse, it ignores the operating band: the plant lives in a ~60 °C window, so ±7 °C is not 1% of anything meaningful. The defensible framing is ±6 °C MAE, 22–25% better than persistence, verified live — and that is the only framing this project uses.

05The models — everything we tried, honestly compared

Four model families were built and raced on identical data, plus a served blend and a set of measured rejections. Trees won, and the reason is structural: this is medium-sized tabular data with heterogeneous physics, exactly where gradient boosting dominates deep learning (Grinsztajn et al., NeurIPS 2022 — and our own bench agrees).

07Live validation — the number that can't be gamed

Every 30 seconds, shadow mode logs a prediction; five minutes later it scores it against what the plant actually did. 68,117 predictions have matured this way. This is the evidence a control-room operator should care about:

The floor — and what it would take to go below it

Measured from the year-long 1-second export: the true 5-minute temperature change averages 11.6 °C; ~0.7 °C of every score is thermocouple jitter on the truth itself; and the test-picked ensemble ceiling equals what v7 already serves. The remaining error is dominated by minute-scale fuel calorific-value variation in the AFR stream — which no current sensor measures. Going materially below ~5.5 °C is an instrumentation decision (online fuel quality/calorimetry), not a modelling one.
